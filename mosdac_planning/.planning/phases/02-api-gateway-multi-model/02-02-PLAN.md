Implement API key authentication via Bearer token and Redis-backed rate limiting middleware. This plan delivers the security and traffic control layer that protects vLLM backends from unauthorized and excessive requests.

Purpose: Without auth, any client can consume GPU resources. Without rate limiting, a single client can exhaust capacity. Both are prerequisites for production use.
Output: FastAPI app with HTTPBearer auth dependency, slowapi+Redis rate limiter, and API key store.
</objective>

<task type="auto">
  <name>Task 1: Implement API key authentication with Bearer token verification</name>
  <files>
    src/gateway/auth.py
    src/gateway/main.py
  </files>
  <action>
    Create API key authentication using FastAPI's HTTPBearer security scheme:

    1. Create src/gateway/auth.py:
       - Use fastapi.security.HTTPBearer (not custom header parsing — handles scheme case normalization per research Pitfall 7)
       - security = HTTPBearer()
       - Create API key store: load keys from JSON file (settings.api_keys_file)
         - File format: {"key_hash": {"name": "client-name", "is_active": true, "rate_limit": "100/minute"}}
         - Keys are stored as SHA-256 hashes, not plaintext
       - Function: async def verify_api_key(credentials: HTTPAuthorizationCredentials = Security(security)) -> dict
         - Hash the incoming token with hashlib.sha256
         - Look up hash in the key store
         - If not found or not active: raise HTTPException with status_code=401 and OpenAI-compatible error detail:
           {"error": {"message": "Invalid authentication credentials", "type": "invalid_request_error", "code": "invalid_api_key", "param": None}}
         - Return the API key metadata dict (name, is_active, rate_limit)
       - Use passlib for timing-safe comparison if available, otherwise hashlib.sha256 with constant-time comparison via hmac.compare_digest

    2. Wire auth into src/gateway/main.py:
       - Create FastAPI app instance
       - Add a test endpoint: GET /health that returns {"status": "ok"} (no auth required)
       - Add a test endpoint: GET /v1/auth-test that requires verify_api_key dependency and returns {"authenticated": True, "key_name": ...}

    Do NOT hand-roll Bearer token parsing — use HTTPBearer. Do NOT store plaintext API keys — always hash. Do NOT return generic 401 — use OpenAI error schema.
  </action>
  <verify>
    - curl http://localhost:8000/health returns 200 with {"status": "ok"}
    - curl http://localhost:8000/v1/auth-test (no auth header) returns 401 with OpenAI error schema
    - curl -H "Authorization: Bearer invalid-token" http://localhost:8000/v1/auth-test returns 401
    - curl -H "Authorization: Bearer <valid-key>" http://localhost:8000/v1/auth-test returns 200 with authenticated response
    - curl -H "Authorization: bearer <valid-key>" (lowercase) http://localhost:8000/v1/auth-test returns 200 (case insensitive)
  </verify>
  <done>
    - src/gateway/auth.py exports verify_api_key and security
    - HTTPBearer handles Bearer token extraction with case-insensitive scheme
    - API keys are stored as SHA-256 hashes in a JSON file
    - Invalid/missing tokens return 401 with OpenAI-compatible error schema
    - Valid tokens return API key metadata dict
    - src/gateway/main.py has FastAPI app with auth dependency wired to test endpoint
  </done>

<task type="auto">
  <name>Task 2: Implement Redis-backed rate limiting with slowapi</name>
  <files>
    src/gateway/rate_limiter.py
    src/gateway/main.py
  </files>
  <action>
    Create rate limiting middleware using slowapi with Redis storage:

    1. Create src/gateway/rate_limiter.py:
       - Import slowapi.Limiter and use Redis storage backend
       - Create key function: def get_api_key_identifier(request: Request) -> str
         - Extract Bearer token from Authorization header
         - If token present, return the raw token (for per-key rate limiting)
         - If no token, return request.client.host (fallback for unauthenticated requests)
       - Create limiter: Limiter(
           key_func=get_api_key_identifier,
           storage_uri=settings.redis_url,
           default_limits=[settings.rate_limit_default],
         )
       - Export the limiter instance

    2. Wire rate limiting into src/gateway/main.py:
       - Import and register slowapi middleware with the FastAPI app
       - Add @limiter.limit decorator to the /v1/auth-test endpoint (override default: "60/minute")
       - Configure the 429 response handler to return OpenAI-compatible error schema with Retry-After header:
         {"error": {"message": "Rate limit exceeded", "type": "invalid_request_error", "code": "rate_limit_exceeded", "param": None}}
       - Use slowapi's exception handler override or custom exception_handler for RateLimitExceeded

    Do NOT use in-memory rate limiting (dict-based) — it breaks across workers per research Pitfall 3. Do NOT hand-roll Lua scripts — use slowapi which handles token bucket timing and Retry-After headers.
  </action>
  <verify>
    - Send 60+ requests to /v1/auth-test within 60 seconds with valid Bearer token
    - First 60 requests return 200
    - 61st request returns 429 with Retry-After header
    - 429 response body matches OpenAI error schema: {"error": {"code": "rate_limit_exceeded", ...}}
    - Different Bearer tokens have independent rate limit counters (send 60 with key A, then key B — key B should succeed)
  </verify>
  <done>

    - Rate limiting is per-API-key (different tokens have separate counters)
    - Rate limit exceeded returns 429 with Retry-After header
    - 429 response body matches OpenAI error schema
    - slowapi middleware is registered on the FastAPI app
    - Rate limits persist across app restarts (stored in Redis, not memory)
  </done>
