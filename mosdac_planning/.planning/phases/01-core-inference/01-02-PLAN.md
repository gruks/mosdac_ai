<objective>
Create a lightweight FastAPI sidecar that provides the `/health` endpoint with GPU utilization metrics — the one thing vLLM does not provide natively in the required format.

Purpose: vLLM's built-in `/health` is a basic liveness check (returns 200 OK). INF-05 requires GPU utilization metrics (per-GPU usage, memory). This sidecar fills that gap without wrapping or replacing vLLM's OpenAI-compatible server.

Output: FastAPI application with /health endpoint returning model status and GPU metrics.
</objective>

2. inference/gateway/health.py with function `get_health()` that:
   - Calls pynvml.nvmlInit() at start, pynvml.nvmlShutdown() at end (use try/finally)
   - Iterates over all GPUs via pynvml.nvmlDeviceGetCount() and pynvml.nvmlDeviceGetHandleByIndex(i)
   - For each GPU, collects: gpu_id, utilization (%), memory_used_mb, memory_total_mb, memory_utilization (%)
   - Checks vLLM server health by making HTTP GET to http://localhost:8000/health (the vLLM built-in endpoint) using httpx with 5-second timeout
   - Returns dict: {"status": "healthy"|"degraded"|"unhealthy", "model": "Qwen/Qwen2.5-Coder-32B-Instruct", "tensor_parallel_size": 2, "vllm_reachable": bool, "gpus": [list of gpu_metrics]}
   - Status logic: "healthy" if vLLM reachable and all GPUs responding; "degraded" if vLLM reachable but some GPU metrics fail; "unhealthy" if vLLM unreachable

3. inference/gateway/main.py with FastAPI app that:
   - Creates FastAPI() instance
   - Defines GET /health endpoint that calls get_health() and returns the result
   - Uses uvicorn to run on host 0.0.0.0, port 8001 (different port from vLLM's 8000 to avoid conflict)
   - Includes `if __name__ == "__main__": uvicorn.run("main:app", host="0.0.0.0", port=8001, reload=False)`
   - Add basic error handling: if pynvml fails (e.g., no NVIDIA drivers), return status "unhealthy" with error message

Do NOT wrap vLLM's OpenAI endpoints — this is ONLY a health sidecar. vLLM serves /v1/chat/completions directly on port 8000.
